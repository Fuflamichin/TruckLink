# TruckLink — Stage 1 starter

Open-source-intended ETS2 companion monorepo: Flutter for Windows, Android and iOS; shared Dart packages. All dashboard values are **DEMO DATA**. No ETS2 SDK plugin is included, and the internet relay is intentionally not implemented.

## Requirements
- Flutter stable (Flutter 3.50+ recommended); Dart 3.9+.
- Windows builds: Visual Studio 2022 or newer with Desktop development with C++ workload.
- Android builds: Android SDK and Android Studio or equivalent command line tools.
- iOS builds and signing: **Mac with Xcode** (even though app sources can be edited on Windows).

## Bootstrap on Windows (PowerShell)
```powershell
flutter doctor -v
./scripts/bootstrap.ps1
cd apps/desktop
flutter run -d windows
```

Start the **demo** WebSocket server from the desktop UI. Find PC IPv4 via `ipconfig`.

For Android, from repo root:
```powershell
cd apps/mobile
flutter devices
flutter run -d <android-device-id>
```

Enter the Windows IPv4 address in the phone app (same trusted Wi-Fi). Ensure Windows firewall allows port 8787 on the **private** profile only. No public internet access should be configured.

### Android cleartext permission for *local demo only*
Flutter Android apps may block ws:// connections by default. The Windows PowerShell bootstrap automatically adds `android:usesCleartextTraffic="true"` and Internet permission in `apps/mobile/android/app/src/main/AndroidManifest.xml`. This is temporary and must be removed when local TLS/pairing ships. For iOS local-network permissions and ATS exceptions must also be configured at implementation time; this repository does not yet claim a tested iOS LAN connection.

## Package structure
- `apps/desktop`: Windows Flutter UI plus demo-only WebSocket server on `0.0.0.0:8787`.
- `apps/mobile`: Flutter client that receives demo snapshot messages.
- `packages/telemetry_core`: immutable telemetry model and serialization.
- `packages/network_protocol`: versioned JSON envelope.
- `packages/design_system`: dark theme and reusable metric card.
- `services/relay_server`: inert placeholder — no public server.

## Checks
```powershell
flutter pub get
flutter analyze apps/desktop
flutter analyze apps/mobile
flutter test packages/telemetry_core
```

## Important safety / release checklist
- The unauthenticated `ws://` server is **only a development harness on a trusted LAN**; do not port-forward 8787, deploy it publicly or distribute it as production-ready.
- Next step: telemetry SDK source adapter, secure local pairing, authenticated WSS/TLS, transport encryption, explicit permissions, reconnect handling, persistence, and tests.
- Windows Flutter build is not available from this Linux preparation environment; platform runners are generated by `bootstrap.ps1` on your PC.
- Choose an explicit OSS license and review third-party telemetry plugin licenses before publishing.
